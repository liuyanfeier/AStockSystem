# Phase1 Consolidated Integrity Design v2

## Evidence truth and versions

Every generation binds a frozen transformation and contracts plus immutable input descriptors. Re-decode those exact inputs and compare complete facts, lineage and quality sets, not only stored hashes. Increment verifies old generations first and derives the next union exclusively from validated input objects; transaction readback repeats derivation. All public consumers share verification. Frozen v1 bytes and exact registry pins stay under compat/phase1/v1; v1 read-only fixtures can be re-derived with v1 adapters. Unbound historical production capture is uncertified, never retroactively licensed. Unknown versions/pins fail closed.

## Identity and targets

Financial association resolves explicit provider-native identities at the report period and publication date, requiring a single stable security/episode; a supplier's new-code old report needs source/dataset-specific provenance and a compatible report episode. Code reuse, concurrent mappings and unsupported scope stay unknown/conflict. Coverage binds a target scope/hash/dependencies, deriving expectations from known civil sessions and effective listing episodes; all-domain obligations and unknown denominators are exposed separately. Explicit targets can augment known expectations and specify report vintage, taxonomy and rules; absent observations never imply NORMAL/suspension/nonexistence.

## Permission and persistence

V2 uses an isolated additive schema. Before any durable claim, atomically retain actual approval/human payloads, byte references, version/SHA/plan/root/destination/consumption/time; authorization hashes bind attempts, events and physical source/receipt. Historical validation uses execution-time pins, never current Git HEAD. Production-shaped tests are confined to marker-bound TEST roots and closed transports; cannot run against this canonical repo.

A derived rebuild owner is bound to canonical root, source store and source namespace, without capture/import permissions. Production source remains production, fixture source remains fixture; derived targets cannot issue HTTP. Read-only source audits, historical authorization and fixed descriptors remain mandatory at build, reopen and query. Independent A/B builds and source increments preserve old inputs and logical content. No original schema is modified.

## Delivery

Reproduce the review's self-consistent EPS/time/source/member attacks across consumers; four financial domains cross identifier changes and revisions; closed production-shaped acquisition → authorization → facts → coverage/query → A/B rebuild → correction/idempotence/audit. Freeze final source before full offline checks and exact-SHA CI. Update the same unlicensed50-member application, expose per-domain finite expansion rules/unknowns, preserve full-history hash guards and disclose costs.
