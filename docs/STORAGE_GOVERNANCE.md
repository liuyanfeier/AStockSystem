# 数据存储治理

2026-10-11 实测。GB 使用十进制，GiB 使用 2^30；文件逻辑长度与磁盘分配 blocks 分开。
完整路径/hash/副本删除候选属于私有材料，不提交真实行或数据库。
本批真实数据删除为 0；下面全部私有清理仍待用户确认。

## 必须保留

- 原 warehouse/metadata/capture 三库、新 RAW_ONLY catalog 与实际消费/失败/未知账本。
- 真实原始响应/raw、官方文献来源、真实审批原字节、不可替代版本/vintage、交易和复盘记录。
- 历史来源 decoder、唯一有效备份、失败复现场景、必要 source pins 及可读恢复材料。
- 原始财务/行情观察与更正，不能以“可重建”名义删除无法重新获得的历史来源。

原三个库与新 catalog 均已受管只读核查并证实前后 hash 不变。数据文件全量 hash 盘点只读进行；
初始 155,655 文件的最终同字节复核见 REPOSITORY_RESET。不能把“当前数据很旧”当删除理由。

## 50GB目标 / 100GB上限

容量范围包含项目代码、Git、本地工具、data/private/raw/curated/warehouse、生成报告及备份副本；
外置冷备也要列独立账，不通过移动文件隐瞒总量。原全历史2TiB方案仅作历史，不适用当前建设。

每次新数据任务先估算字段/行数/窗口、缓存与峰值临时空间，获取最小业务所需数据；
每月及大批导入前做一次容量盘点。超过50GB目标先评估缓存、重复演练与可重建派生物，
扩充数据范围前给出预算/取舍；达到100GB上限停止新增占用并处理容量，不自动删来源。
这些是容量治理政策，不是已实现后台监控。

不可替代 raw/审批/消费/交易记录长期保留并加密异盘备份。派生 feature/report cache
采用输入hash+代码/参数可重建记录与滚动保留；真实研究卡与交易日志不能当缓存处理。
Research V1 优先连续近期窗口与增量，不再默认申请全部公司/年份/vintage。

## 重复运行盘点

~~~bash
export PATH="$PWD/scripts:$PATH"
uv run --offline --frozen python scripts/repository_inventory.py \
  --output data/private/repository-governance/NEW_DATE/capacity.json
~~~

需要同字节证明时显式加 --hash-data；默认仅做文件统计，不打开数据库、不跟随符号链接、不读凭据内容。
输出必须在指定 ignored 治理目录并禁止覆盖；该目录排除出基础盘点，需单独计入总容量。
数据库业务读回仍通过 warehouse_connection；本脚本不签发采集/删除/研究准入许可。
