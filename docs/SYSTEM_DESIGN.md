## 清理与长期生命周期

第一批按来源/依赖/保留证据/重建与恢复核验缩小精确范围，再确认实际清理。
用户已批准并完成旧pytest根内1626个合成子目录及707别名清理，保留382个保护目录；
九个演示根未纳入已执行范围。精确Hash、回执与清理后容量见[CURRENT_STATE](CURRENT_STATE.md)，不将启动候选当作全部可删空间。

随后拆解旧演练与外部工作目录：

1. Raw、消费、失败现场和真实记录留唯一权威版本，并保留必要备份。
2. 可再生SQL库、重建库、测试副本只保留必要锚点与恢复说明。
3. 对压缩归档实际测压缩率、校验清单、隔离解包及读回；验证后再提出移除原目录。移动到外置盘仍计项目总量，不把移动称作总量减少。
4. 迁移期间不生成整套额外备份；先估峰值，只处理一个有界批次。

新增产物必须登记category、owner、run/source引用、大小、重建命令、保留规则、保护原因与引用关系。没有这些字段的任务不得自动留下长期目录。

## 目标架构

```mermaid
flowchart TD
  S[已授权来源与手工输入] --> E[数据与证据：不可变来源和可知时间]
  E --> F[数值特征与市场行业观察]
  E --> R[公司主题研究：支持、反证、估值与事件]
  F --> T[版本化策略与交易规则]
  R --> D[计划与每日决策]
  T --> D
  A[私有账户事实与实际成交] --> P[持仓风险与退出检查]
  E --> P
  R --> P
  P --> D
  D --> O[中文收盘简报、盘前重点、简单录入]
  O --> U[用户人工确认与券商执行]
  U --> A
  T --> X[统一规则的回放与前瞻PAPER]
  E --> X
  X --> L[归因、纪律与策略复盘]
  A --> L
  L --> V[提出并验证新版本]
```

采用单机模块化应用，不拆微服务。来源存储保留既有Research Store；新增业务工作区与冻结源库分开，沿用DuckDB、受管锁和单写入路径。M1首段复用独立工作Journal的五表容器，增加类型化INPUT/ACCOUNT事件，不向冻结源库写入或升级。未来对象超出事件容器时采用独立版本schema，保存研究版本、计划、账户、动作和运行状态。

应用服务返回明确的MarketSnapshot、FeatureSnapshot、ResearchThesis、Setup、TradePlan、PositionReview和DecisionItem。报告及以后页面消费同一应用服务；不再把公开报告JSON作为核心数据接口，也不把私人Journal放进通用行情计算。

策略观察资格、研究判断、PAPER资格、真实账户风险和执行条件分别表达。缺账户不阻止观察/实验，满足Setup不产生真钱许可；已有持仓的风险不因报价或其他资料缺失消失。确认已阅不代表风险已解除。

首个策略研究候选为日线趋势回踩，突破及简单趋势为对照；按用户数周至数月的节奏设计。[首轮研究合同](STRATEGY_RESEARCH_V1.md)固定参数、进出/取消、基线、成本、可成交约束和评估。M2已实现同一规则判定供日常观察和合成PAPER使用，旧V0执行循环已被共享内核替换；真实PAPER与策略优势未验收。AI研究干预按真实取得时点前瞻留档，单独归因，不能回填历史。

全市场数值扫描保留，深度研究集中于持仓/计划/接近Setup的对象。公司、行业、主题、估值与催化应解释经济驱动和反证；不扩建通用新闻/PDF档案平台。首先支持收盘后和盘前，后续提醒能力须实际部署和验证。
